# Scenario Map MVP

## Назначение

Интерактивная карта связывает аналитическое описание пользовательского сценария с реальными состояниями UI-пилота. Один шаг имеет один стабильный `id`, текстовое представление и экран. Переход между режимами не меняет выбранный шаг.

## Поверхность

Основная поверхность — **Explore**: пользователь перемещается по открытой карте и выбирает узлы. Вторичная — **Inspect**: выбранное воспроизводимое HTML-состояние пилота открывается в 100% масштабе, остаётся интерактивным и последовательно листается.

## Аудитория

- бизнес — просматривает путь и результат без чтения реализации;
- аналитик — проверяет условия, действия системы и развилки;
- дизайнер — видит последовательность реальных состояний;
- frontend и QA — используют шаги как перечень реализуемых и проверяемых состояний.

## Сценарии MVP

### ВНД · фоновая проверка

1. `vnd.start` — ассистент просит прикрепить ВНД.
2. `vnd.running` — документ и стандарт выбраны, AgentActivity показывает фоновую работу.
3. `vnd.history-running` — пользователь видит работающий диалог в истории.
4. `vnd.unread` — пользователь ушёл в другой чат; завершённый результат отмечен звёздочкой.
5. `vnd.result` — результат открыт, ассистент предлагает сохранить ВНД.
6. `vnd.saved` — пользователь подтверждает сохранение словами, ассистент сообщает папку.

### Ответ готов в другом чате

1. `reply-ready.switch` — проверка ВНД запускается в живом экране, пользователь выбирает другой чат из истории.
2. `reply-ready.menu` — звёздочка видна сразу на кнопке истории, панель закрыта.
3. `reply-ready.unread` — пользователь открывает историю и видит звёздочку рядом с исходным чатом.
4. `reply-ready.read` — пользователь открывает исходный чат с готовым ответом, обе отметки исчезают.

В первом живом экране можно пройти весь сценарий. Проверка использует тот же фоновый сценарий ВНД, что и прототип. Остальные экраны открываются сразу в выбранном состоянии.

### Настройки агента

1. `settings.history` — вход через историю диалогов.
2. `settings.overview` — второй слой drawer с историей и памятью агента.
От общего обзора на одном канвасе расходятся две ветки:

- Удаление одного факта. `settings.confirm` открывает подтверждение, `settings.updated` показывает обновлённый список и счётчик.
- Очистка всей памяти. `settings-clear.confirm` открывает подтверждение, `settings-clear.empty` показывает пустую память. Кнопка очистки недоступна, история чатов сохранена.

В режиме «Открыть 100%» можно подтвердить очистку и увидеть пустую память в том же живом экране. На развилке доступны обе кнопки перехода. Прежние ссылки с `scenario=settings-clear` открывают соответствующий шаг общего канваса.

### Feedback-агент

Карта разделяет четыре семейства: CSI после ВНД (8 шагов), CSI по запросу (4), жалоба / помощь (5), идея / похвала (4). Они покрывают оценки 1–5, отказ, комментарий или пропуск, mock success/error, один вопрос о сервисе и сохранение неизвестного сервиса без выдуманного match. Помощь остаётся задачей и не записывается как жалоба.

Всего карта содержит 37 стабильных состояний. Из них 16 относятся к ВНД, истории и настройкам, 21 — к feedback-агенту. Полный перечень step ID хранится в `pilot/scenario-map/model.ts` и проверяется тестами вместе с уникальностью screenshot и live URL.

## Возможности MVP

- два синхронизированных режима: «Сценарий» и «Экраны»;
- выбор одного из семи сценариев;
- сохранение выбранного шага при переключении режима;
- прямые ссылки через query-параметры `scenario`, `step`, `view`;
- переход от текстового узла к тому же экрану и обратно;
- экранный canvas с масштабированием и панорамированием;
- открытие выбранного экрана как живого HTML в 100% масштабе;
- последовательная навигация «Назад / Далее»;
- клавиатурная навигация и reduced-motion fallback.

## Техническая схема

- отдельное Vite multi-page приложение: `/chat-ui/scenario-map/`;
- общий source branch `universal-agent-ui-pilot`;
- данные сценариев отделены от React-представления;
- реальные снимки UI-пилота хранятся в `pilot/public/scenario-map/screens` и используются для обзорного canvas;
- каждый шаг имеет детерминированное live-состояние пилота по URL `?atlas=<step-id>&embed=1`;
- `build:pages` собирает чат и карту одним воспроизводимым артефактом;
- deploy полностью заменяет `gh-pages` результатом общей сборки — ручного редактирования assets нет.

## Не входит в MVP

Редактирование карты, комментарии, роли доступа, сравнение версий, автоматическое снятие экранов и все сценарии универсального агента.

## Проверка готовности

- текстовая и экранная карты показывают одинаковое количество шагов;
- выбор шага синхронен между режимами и URL;
- каждый экран открывается в 100% масштабе как интерактивный HTML, а не увеличенный снимок;
- прямой URL восстанавливает сценарий, шаг и режим;
- карта работает на desktop и mobile без потери доступа к шагам;
- исходный Chat UI продолжает открываться по `/chat-ui/`;
- tests, typecheck и production build проходят;
- оба URL проверены в браузере после публикации.
