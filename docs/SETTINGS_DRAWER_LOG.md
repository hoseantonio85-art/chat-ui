## Исследование UI kit

- В `ui-kit-0.307.0` компонент `Button` поддерживает `fullWidth`, варианты `danger`, `secondary`, `ellipse` и размеры `XS`/`S`.
- `variant='ellipse' size='S' iconOnly` даёт системную круглую кнопку высотой 40 px. Для возврата в компонентах продукта используется иконка `EIconName.previousLarge`.
- Эталон заголовка найден в `components-0.269.0/package/src/components/Drawer/Drawer.tsx`: UI-kit `Button` с `variant='ellipse'`, `size='S'`, `iconOnly`, `previousLarge`; контейнер заголовка использует `gutter={16}`.
- `Popover` экспортируется из `@sber-orm/ui-kit` и принимает `anchor`, `open`, `placement`, `fallbackPlacements`, `offset`, `withArrow`, `container`, `disablePortal`, `onClose` и обычные свойства `div`.
- В vendored UI kit текущего пилота уже есть `Popover`, `fullWidth`, `settings` и `previousLarge`; обновление зависимости для этой задачи не требуется.
- Сам `Popover` отвечает за визуальный контейнер и позиционирование, но управление состоянием, outside click, Escape и возвратом фокуса остаётся на стороне вызывающего компонента.

## Найденные продуктовые паттерны

- Measures и Risks используют один паттерн destructive confirmation: trigger хранит `ref`, `Popover` получает `anchor={ref.current}`, `open`, `placement='top-end'`, fallback `bottom-end` и стрелку.
- Внутри Popover: короткий заголовок, пояснение и ряд из двух UI-kit Button. «Отмена» — `variant='secondary'`, подтверждение — `variant='danger'`; обе кнопки `size='XS'` и `fullWidth`.
- Для удаления файлов внутри ограниченных контейнеров встречается `disablePortal`; для карточек используется portal по умолчанию. В нашем drawer `overflow: hidden`, поэтому подтверждение должно рендериться через portal по умолчанию и получить явный z-index, иначе его может обрезать drawer.
- Ширина product Popover обычно 270–374 px; для drawer нужна адаптивная ширина около 300–320 px с ограничением по viewport.
- Подтверждение одного объекта в продукте также выполняется через Popover, а не inline-блоком или нативным `confirm()`.

## Исправление подтверждения и ветка очистки памяти

- UI-kit Popover рендерится через портал и не передаёт внешний ref. Обработчик `pointerdown` из-за этого принимал нажатия в окне подтверждения за клики снаружи и закрывал его до выполнения действия. Теперь обработчик определяет принадлежность клика по корневому элементу Popover.
- В карте появилась ветка «Очистка памяти». В живом экране можно удалить все факты и увидеть «Память пуста». Отдельные шаги воспроизводят список, открытое подтверждение и пустую память.
